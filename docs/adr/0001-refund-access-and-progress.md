# End course access only after a refund is confirmed issued

Approving a Refund Request authorizes repayment but does not establish that the learner has received it. Course access therefore continues through an Open Refund Request and a Pending or Failed Refund, and ends only when the Refund is confirmed Issued. A decline leaves access unchanged.

Course progress is retained when access ends and resumes after repurchase. Erasing learning history would make a financial decision unnecessarily destructive; retaining it lets returning learners continue where they left off.

Issuance removes only the access granted by the refunded purchase. A separate valid purchase continues granting access even if an older purchase is refunded later. Existing comments and reviews remain; posting and editing follow existing access rules.

Support manually records payment outcomes while repayment happens outside the app. Approval creates a Pending Refund; Support can subsequently record it as Issued or Failed. Both the new Support role and Admin have refund review authority. Submission eligibility rules are outside this feature's scope.
